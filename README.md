# 量化交易 Agent · 多智能体指数择时系统

一个**可复现、可解释**的多 Agent 择时系统：5 个职责单一的 Agent 协作，把「数据采集 → 技术面 / 新闻情绪 / 宏观贸易 → 风险预算 → 交易决策」串成一条流水线，对沪深 300ETF 输出 **买入 / 卖出 / 持有** 三类信号，并用 T+1 成交的成本模型做回测。

- 数据全部来自公开接口，不依赖任何付费数据库
- 每个信号的每一分都能追溯到具体规则（不是黑盒打分）
- 回测严格 T+1 执行、含佣金与滑点，随机种子固定，同配置结果完全一致
- 单元测试覆盖指标、Agent 规则、无未来函数、T+1 成交、可复现性

---

## 1. 它解决什么问题

指数择时的难点不是「预测涨跌」，而是三件事：

1. **信号要多源但别打架**——技术面、情绪、宏观各自有噪声，怎么合成？
2. **仓位谁说了算**——看多不代表要满仓，波动率、回撤谁来做约束？
3. **亏损时能不能复盘**——这次亏钱是因为宏观判断错，还是风险预算压太狠？

本项目用「职责分离 + 加权可解释投票 + 独立风险预算」回答这三个问题。

## 2. 架构

```
                        ┌──────────────────────────────┐
                        │  Collector 数据采集 Agent      │
                        │  校验完整性 / 新鲜度 / 特征对齐  │
                        └───────────────┬──────────────┘
                                        │  统一特征行（每日一行）
        ┌───────────────────┬───────────┴───────────┬────────────────────┐
        ▼                   ▼                       ▼                    ▼
┌───────────────┐  ┌────────────────┐    ┌──────────────────┐  ┌──────────────────┐
│ Technical     │  │ Sentiment      │    │ Macro            │  │ Risk             │
│ 技术分析 Agent │  │ 新闻情绪 Agent  │    │ 宏观贸易 Agent    │  │ 风险管理 Agent    │
│ 趋势/反转/回踩 │  │ 词典情感+衰减   │    │ 海关同比 z-score  │  │ 波动率目标+VaR    │
└───────┬───────┘  └────────┬───────┘    └────────┬─────────┘  └────────┬─────────┘
        │ 方向分 [-1,1]      │ 方向分               │ 方向分              │ 仓位上限
        └────────────────────┴──────────┬──────────┴────────────────────┘
                                        ▼
                        ┌──────────────────────────────┐
                        │  Decision 交易决策 Agent       │
                        │  加权合成 + 确认机制 + 调仓带   │
                        │  → BUY / SELL / HOLD         │
                        └───────────────┬──────────────┘
                                        ▼
                        回测引擎（T+1 开盘成交，含成本）→ 报告/归因
```

### Agent 输出契约

所有 Agent 统一返回 `Signal`：

| 字段 | 含义 |
| --- | --- |
| `score` | 方向分 ∈ [-1, 1]，正数看多 |
| `confidence` | 置信度 ∈ [0, 1]，由数据质量/样本量决定 |
| `reasons` | 人可读依据（逐条规则 + 实际数值） |
| `evidence` | 结构化证据（如 `position_cap`、`regime`），供下游与报告使用 |

决策层只做三件事：按权重合成方向分、套用风险预算上限、执行上下文规则。**风险 Agent 不参与方向投票**，只给仓位上限——因为它天生只可能给出 ≤ 0 的分数，放进平均会长期把综合分往下拽，让系统几乎不建仓。

## 3. 数据底座

数据仓库分维度表 + 事实表，SQLite 默认可跑，换 MySQL 只需改 `config.yaml` 的 `db.url`。

| 表 | 内容 | 说明 |
| --- | --- | --- |
| `fact_trade_monthly` | 海关月度进出口（出口/进口/差额/同比/环比/累计） | 覆盖 2008-01 至最新月份，一次抓取 200+ 期 |
| `fact_market_daily` | 沪深 300ETF(510300) 与沪深 300 指数(000300) 日线 | 前者用于成交，后者作为业绩基准 |
| `fact_fx_daily` | 美元兑离岸人民币日线 | 宏观辅助数据 |
| `fact_news` | 7×24 财经快讯 + 词典情感分/标签 | 用于情绪 Agent |
| `fact_signal_daily` | 每日决策、目标仓位、归因 JSON | 回测/实盘信号可追溯 |
| `dim_agent` / `dim_region` | Agent 元数据、贸易区域维度 | 区域维度已建表，等待双边数据接入 |

写入是**按主键先删后插**的幂等 upsert，重复跑 ETL 不会产生脏数据；同时会把数据导出到 `data/snapshot/*.csv`，保证离线也能复现同一份结论。

多维检索示例（`python -m qtagent query`）：

```sql
SELECT trade_month, export_usd, export_yoy, export_mom
FROM fact_trade_monthly
WHERE region_code = :region
  AND (:start_month IS NULL OR trade_month >= :start_month)
  AND (:end_month   IS NULL OR trade_month <= :end_month)
ORDER BY trade_month;
```

流向（出口/进口/差额）与口径（当月/累计）在 `query_trade()` 里用白名单映射到列，既支持多维查询又不会拼 SQL 注入。

## 4. 决策公式

```
方向分  score  = Σ(w_i · s_i · c_i) / Σ(w_i)        i ∈ {技术, 情绪, 宏观}
预算    cap    = 波动率目标 / 实际波动 × 回撤惩罚（Risk Agent）
目标仓位 target = cap · clip(score / full_score, 0, 1)      # A 股现货不开空
```

方向分再叠加三条上下文规则：

1. **确认机制**：连续 N 日同向才建仓，过滤单日噪声；
2. **中性带**：分数落在 `exit_threshold ~ entry_threshold` 之间时维持现有仓位，避免来回折腾；
3. **记忆**：保留最近 120 条决策，用于计算确认天数与归因复盘。

## 6. 回测协议（为什么这个结果可信）

- **T+1 成交**：T 日收盘后出信号，T+1 开盘价成交，含单边滑点 5bp、佣金 3bp，按 100 份整数倍下单
- **无未来函数**：所有滚动指标只用过去数据；海关数据按发布滞后 25 天对齐；收盘后（≥15:00）发布的新闻顺延到下一自然日
- **可复现**：无随机数，同数据同配置两次回测净值逐点相同（有单测覆盖）
- **可解释**：每日归因写进 `fact_signal_daily.contributions`，报告里能看到「这一分是谁贡献的」

## 7. 回测结果（2023-04-04 ~ 2026-11-17，沪深300ETF）

| 指标 | 策略 | 基准（沪深300） |
| --- | --- | --- |
| 累计收益 | **-5.22%** | -2.95% |
| 年化波动 | 8.27% | — |
| 最大回撤 | **-13.74%** | -24.09% |
| 平均仓位 | 24.33% | 100% |
| 交易回合 | 25 | — |
| 胜率 | 20.00% | — |
| 夏普 | -0.43 | — |

**这个结果说明什么（不粉饰）：**

1. **方向判断没有 alpha**：累计收益跑输基准 2.3 个百分点。因子检验（`research/factor_ic.py`）显示，本区间沪深300ETF 的 `ret20`、`bias20`、`MA20` 斜率与未来 20 日收益的 Spearman IC 全部为负（约 -0.03 ~ -0.07），即**动量在该区间是反向因子**，而默认技术模式是顺势的——这是最直接的原因。
2. **风控部分是有效的**：最大回撤从 -24.09% 压到 -13.74%，平均仓位只有 24%，也就是「用四分之一的仓位拿到了七折的回撤保护」。
3. **胜率低但盈亏比高**：平均盈利 43,954 元 vs 平均亏损 13,601 元，属于典型的「少数大赚、多数小亏」趋势型分布，而非稳定小赢。
4. **成本不可忽视**：换手 43.5 倍、单边成本 8bp，累计成本拖累约 2%~3%，与超额亏损同量级。

**如果要继续做（按优先级）：**
- 把「趋势 / 反转」做成显式的状态切换（用波动率区间或趋势强度判定），而不是固定一种模式；
- 接入更长历史的新闻与情绪数据源，让情绪 Agent 不再长期走降级通道；
- 加入第二标的（如债券 ETF）做风险平价，把「空仓」升级为「切换到低相关资产」；
- 用滚动窗口做 walk-forward 验证，替掉当前单次样本外切分。

### 已知局限

- **新闻历史太短**：免费快讯接口只能回溯约 10 天，所以回测中情绪 Agent 大部分时间走「量价代理」降级通道，并在 `evidence.degraded` 里标记。要覆盖长历史需要付费新闻源。
- **单标的、只做多**：标的为沪深 300ETF，没有做空与跨品种对冲，因此熊市里最好的结果就是空仓。
- **区域/商品结构维度未接入**：`dim_region` 已建表，但公开源拿不到稳定的中美双边分商品数据，代码预留了接入位而不是编造数据。
- **参数存在过拟合风险**：`sweep.py` 用样本内选参、样本外验证的方式做敏感性研究，仍然不能完全排除过拟合。

## 8. 目录结构

```
quant-agent/
├── config/config.yaml          # 全部可调参数（数据源、Agent、回测成本）
├── src/qtagent/
│   ├── datasource/             # 东财接口 + 离线快照两种数据源
│   ├── storage/                # 表结构、幂等写入、多维检索
│   ├── features.py             # 特征工程（含防未来函数的对齐逻辑）
│   ├── indicators.py           # 指标纯函数
│   ├── agents/                 # 五个 Agent + 决策层
│   ├── orchestrator.py         # 流水线编排与数据流转边界
│   ├── backtest/               # 回测引擎、绩效指标、报告
│   └── cli.py                  # build-db / signal / backtest / tune / query
├── research/factor_ic.py       # 因子 IC 检验（决定技术 Agent 模式）
├── scripts/sweep.py            # 参数敏感性研究（样本内/样本外）
├── tests/                      # 指标、Agent、流水线一致性测试
├── data/snapshot/              # 冻结的数据快照，保证可复现
└── reports/                    # 回测报告、净值图、调参结果
```
